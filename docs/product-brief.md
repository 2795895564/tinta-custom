## 0. 一句话

`[已决定]` **一个用起来顺手的个人 Markdown 工作区：阅读、编辑、管理文件都不打断思路。**

> A personal Markdown workspace that feels effortless: read, edit, and manage files without friction.

## 1. 为谁

- 主要用户：你自己。
- 典型状态：本地有一堆 Markdown 文件，经常阅读、偶尔修改，习惯键盘，讨厌重复操作和状态丢失。
- 不是为团队协作、不是为云端知识库、不是为不写 Markdown 的人。

## 2. 三个 Job

`[已决定]` 三个 Job 都属于 V1 产品范围；V1 只保证一条闭环路径。

| Job | 用户想要的结果 | 失败是什么样 |
| --- | --- | --- |
| **阅读** | 打开就能读，排版舒服，不被打断 | 找文件花很久、打开慢、界面抢注意力 |
| **编辑** | 需要时能改，改完可靠保存 | 进入编辑很绕、保存不确定、丢内容 |
| **管理** | 仓库/目录/文件能快速找到、打开、整理 | 记不住文件在哪、操作不可逆、状态丢失 |

## 3. 主循环

```text
打开软件
  → 定位（首页 / 快速跳转 / 最近文件）
  → 阅读
  → 需要时进入编辑
  → 保存
  → 回到定位 / 继续阅读
```

衡量“顺手”的硬指标（可以改）：

- 从启动到开始阅读：≤ 2 个动作。
- 在仓库里定位任意文件：≤ 3 个动作。
- 从阅读进入编辑：1 个动作。
- 保存：1 个动作；关闭不丢内容。
- 回到首页/切换仓库：≤ 2 个动作。

## 4. 界面与职责

两个整页、一个浮层、一个模态（状态定义见 [interaction-state-machine.md](interaction-state-machine.md)）：

| 表面 | 类型 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| **Home** | 整页 | 仓库、目录、文件管理、进入文档 | 不读长文、不编辑正文 |
| **Document** | 整页 | 阅读、编辑、预览 | 不做仓库管理、不弹文件树 |
| **Quick Jump** | 浮层 | 瞬移：标签、最近、仓库搜索 | 不编辑、不管理文件 |
| **Settings** | 模态 | 偏好控制面 | 不做导航、不拥有文档状态 |

仓库选择是 Home 的一个子状态（`Home.Picker`），不是第四个表面。

## 6. V1 范围

`[已决定]` 以下是 V1 边界；后续变更需要更新本页和 `dev-status.md`。

**做：**

- 阅读：打开 md、主题、阅读位置、基本目录。
- 编辑：源码编辑、预览、保存、未保存提示。
- 标签：打开/切换/关闭；会话恢复。
- Home：仓库选择、目录浏览、打开文件、搜索当前目录。
- Home 文件操作：单选的**新建文件/文件夹、重命名、删除到回收站**。
- Quick Jump：标签 + 最近 + 当前仓库文件（需要索引）。
- Settings：最小偏好集 + 固定/可配置键位的第一版。
- Esc 模型：永不退出。

**先不做（V1.5 / V2）：**

- 文件移动、拖拽、多选、撤销文件操作、批量重命名。
- 仓库管理页、重新定位、多仓库高级操作。
- 云同步、插件、导出增强、多窗口高级编排。
- 主题编辑器、复杂动画、自定义布局。

## 7. V1 的验收走查

V1 不是“功能都做完”，而是下面这条路径能一次性走通：

```text
启动 → Home（上次仓库）
  → 新建文件夹 / 新建文件
  → 打开文件阅读
  → E 进入编辑
  → 输入并 Ctrl+S 保存
  → Esc 回到阅读
  → Esc 回到 Home
  → 重命名一个文件
  → 删除到回收站（确认）
  → Ctrl+K 快速跳转并打开另一个文件
  → 关窗、重开：session 恢复
```

这条路径上的每一步都顺畅，V1 才算成立；其他都是之后的第二条路径、第三条路径。

## 8. 成功标准

用一周真实使用来判断，而不是看功能清单：

- 我是否愿意默认用它读 md？
- 找文件是否比 Explorer 快？
- 阅读 30 分钟是否没有被界面打断？
- 编辑保存是否从不担心丢？
- 是否经常按错键或不知道自己在哪？
- 是否因为“还差一个功能”而回到旧工具？

如果答案是否定的，先改主循环，不要加功能。

## 9. 细节停车场

这些不是不重要，而是**现在不该由它们决定方向**：

- 首页行高、图标、列宽、hover 颜色。
- 设置面板的具体控件排列。
- 过渡动画时长。
- 文件操作的具体对话框文案。
- 快速跳转的排序权重。

处理规则：先记下来，等对应的主循环/表面稳定后再做；做的时候只服务一条原则或一个流程。

## 10. 设计管理的最小流程

每周一次，30 分钟：

1. 用 5 分钟走一遍主循环：打开 → 定位 → 阅读 → 编辑 → 保存 → 回首页。
2. 记下卡住的步骤，不先想 UI 细节。
3. 选一个最卡的步骤，做一个小切片。
4. 更新本页的 V1 范围 / 停车场。
5. 不新增表面，除非它对应一个新的 Job。

每次想改细节时问：

> 这个细节服务哪条原则、哪个主循环步骤？如果都说不上，先放进停车场。
